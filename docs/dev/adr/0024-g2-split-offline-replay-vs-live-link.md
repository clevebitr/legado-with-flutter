# ADR-0024 G2 拆分为 G2a（离线回放）与 G2b（真实链路）

- **状态：** Accepted（2026-10-11 架构师复审裁决）
- **日期：** 2026-10-11
- **关联：** `PLAN.md` §4、`docs/dev/book-source.md` §10、ADR-0014、ADR-0023、
  `test/fixtures/html/README.md`

## 背景

`PLAN.md` §4 的 G2 要求「1 个书源全链路离线回放通过；手动真实链路跑通一次」。Phase 2.6 落地时
实测发现**后半条在 Phase 2 不可达成**：

| 步骤 | 实测（2026-10-11） |
|---|---|
| 抽样书源 | 242 条（SourceGo `all.json` 189 + namofree 51 + 其他 2） |
| 四段规则**全用默认规则**（矩阵 #1/#2/#5/#8/#9） | 20 条（8%） |
| 其中站点存活（HTTP 200） | 4 条 |
| 其中搜索路径仍然有效 | **0 条**（404 / 重定向到首页 / 选择器零匹配——2021 年的规则对今天的站点已失效） |
| 12k 条大合集 | release 资源已 404 |

也就是说：**存活的真实书源都需要 `@css:`（矩阵 #12，Phase 3.2）**，而 Phase 2 的引擎按 C-SRC-4
显式拒绝它。「手动真实链路」既不能靠默认规则书源完成，也不能靠 `@css:` 书源提前完成。

架构师同时指出：把「全链路回放」写在测试里自建链路，等于把「测试通过」当成「功能可用」
（`PLAN.md` §6 陷阱 #1 的变种）——回放必须驱动生产链路，否则 `PLAN.md` §1 铁律一
（接口形状只有在端到端跑通一次之后才敢定）没有被服务。

## 决策

1. **G2 拆成两条：**
   - **G2a（Phase 2 出口）：** 1 个**真实书源**完成「搜索 → 详情 → 目录 → 正文」**离线回放**，
     且回放必须驱动**生产链路**（UseCase → `renderUrlTemplate` → `HttpClient` → `RuleEngine`，
     注入假 `HttpClient`），不得在测试内自建链路。**状态：已达成** ——
     `test/features/book_source/domain/usecases/search_books_test.dart` 的 `chain_*` 用例
     断言了四段实际请求的 URL 与 `rulePath`。
   - **G2b（Phase 3.2 之后）：** 手动跑通一次**真实站点**链路。它依赖矩阵 #12（`@css:`），
     因此排在 3.2 之后。
2. **离线回放的语料形态**按 ADR-0023 决策 2：真实书源 JSON（脱敏）+ 页面（**优先真实抓取**；
   站点已不可达时允许按该书源的真实选择器构造，但必须在 `test/fixtures/**/README.md` 标注来源与
   构造依据——`book-source.md` §10 已同步该措辞）。
3. **G2b 不阻塞 Phase 3 开工**，但必须在本 ADR 与 `PLAN.md` 中保持可见，不得静默丢弃。

## 后果

- `PLAN.md` §4 的 Gate 表按本节拆分（G2a / G2b），§3 的 Phase 2 记录登记 G2b 的去向。
- 「测试内自建链路」被明确排除在 Gate 证据之外：Gate 只认驱动生产链路的回放。
- 该拆分**不降低** M0 的验收强度：矩阵 #12（`@css:`）的「已确认」仍要求真实书源回归（Phase 3.7）。
- 抓取页面仍是 §3 矩阵「已确认」与 3.7 的目标；`book-source.md` §10 的措辞已把它保留为**优先**项。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 保留原 G2 措辞，等 Phase 3.2 再判 | Phase 2 将永远无法关账，且「不可达成」这一事实会丢失 |
| 直接删掉 G2b | 真实链路验证是核心风险（方言兼容性只有真实站点能证伪），删掉等于放弃 G1 之后最有价值的那道门 |
| 放宽为「用任何真实书源跑通一次」（含 `@css:`） | 等价于把 Phase 3.2 的工作提前到 Phase 2，违反竖切优先（`PLAN.md` §1 铁律一） |
| 用构造页面声称「真实链路已跑通」 | 构造页面没有真实站点的编码、重定向、反爬与页面漂移，证明不了兼容性 |
