# ADR-0063 云 TTS：立项与待裁决清单

- **状态：** Proposed（2026-10-23，M24-P6；**未生效前不得实现**）
- **日期：** 2026-10-23
- **关联：** ADR-0013（门禁单一出处）、ADR-0054（听书引擎）、ADR-0062（句级高亮）、C-DEP-4 / C-DEP-7、C-SEC-4、C-NET-1、`docs/dev/tech-stack.md` §12

## 背景

听书现在只有**系统 TTS**（`flutter_tts`）：音色取决于设备、无法跨端一致，也不支持「用某个
云端音色读整本书」。真源语料里已有源把朗读交给在线接口，用户也在 M24 范围里要求单独立项。
云 TTS 与已落地的两条链路（音频源播放 / 系统 TTS）差别很大：

- 需要**凭据管理**（token / API key），而本仓红线禁止把 API Key 写进代码或日志；
- 需要**新的网络形状**：多数服务是 POST + JSON，返回音频字节或流，而不是 HTML 页面；
- 需要**缓存与合成队列**（一句话一次请求会很贵、很慢），与 `5.2` 的正文缓存不是同一套键；
- 需要**新的解析/播放路径**：合成结果是音频片段或流，要接回 `AudioPlaybackEngine` 或单独的
  「边合成边播」通道；
- **每家的协议、鉴权、计费都不同**，一次性支持多家会带来许可与维护双重负担。

因此本轮**只立项**：给出范围、待裁决项与验收口径，不动代码。

## 提案范围（建议）

1. **引擎抽象**：`domain/repositories/cloud_speech_synthesizer.dart`，与现有
   `SpeechSynthesizer` 同级，输入（文本、音色、语速、音高）与输出（音频片段流或字节）与具体厂商解耦。
2. **配置面**：设置页新增「云 TTS」一节：引擎选择、端点、凭据、音色、并发与缓存开关；
   凭据只进 `flutter_secure_storage` 类存储（**新依赖需先裁决**），**不得**进日志/导出文件。
3. **合成与缓存**：按「章节 + 分段 + 音色 + 语速」做内容寻址缓存（与正文缓存分表或分 namespace），
   命中即跳过网络；失败不写缓存。
4. **播放接线**：优先复用 `AudioPlaybackEngine`（片段串行播放 + 预取下一段），句级高亮仍按
   ADR-0062 §决策 5 的 `readerTtsHighlighter` 发布。
5. **合规**：明确「凭据由用户自备、请求直接发往用户配置的端点」，仓库不含任何内置 Key；新增依赖
   必须过 C-DEP-7 许可扫描。

## 待裁决（实现前必须回答）

| # | 问题 | 影响 |
|---|---|---|
| 1 | 第一批支持哪家 / 哪种协议（单一厂商 vs 通用「HTTP + JSON」适配器） | 决定是否需要多家适配与许可评审 |
| 2 | 凭据存储方案（`flutter_secure_storage` vs 系统钥匙串插件 vs 用户每次输入） | 新增依赖 + C-DEP-7 审查 |
| 3 | 合成粒度（整段/整句/整章）与缓存 TTL | 成本、延迟与缓存表设计 |
| 4 | 是否允许边合成边播（流式返回）还是先整段合成 | 播放器端口形态 |
| 5 | 与系统 TTS 的关系（并存可选 vs 云优先失败回落） | 设置页与状态机复杂度 |
| 6 | 计费/额度提示是否属于本仓职责 | UI 文案与用户预期 |

## 非目标

- 不做语音识别、不做克隆音色、不做本地神经网络 TTS 模型打包（包体与许可都不可接受）。
- 不在本轮改动系统 TTS 的行为与默认值。

## 验收口径（立项转 Accepted 时必须写进 roadmap）

- 云 TTS 关闭时，行为与今天**完全一致**（系统 TTS 可用、无额外网络请求）。
- 打开后：单章朗读能连续播放，断网 / 凭据错误给出可重试的 `ParseFailure`，日志不含凭据与正文。
- 单章合成请求数与缓存命中可在调试日志里看到，且不突破单源预算（ADR-0036 的口径）。
- 全量门禁 + 三端设备级朗读探针通过；新增依赖许可扫描 `Risky items: none`。
