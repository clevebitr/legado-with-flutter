# ADR-0014 书源功能范围：对标原版阅读的最小实现分期

- **状态：** Accepted
- **日期：** 2026-10-10
- **关联：** C-SRC-1..9、`docs/dev/book-source.md` §3、ADR-0008

> **2026-10-11 事实附注（不改变任何决策）：** 上游 `gedoor/legado` 仓库已**清空**
> （默认分支只剩侵权公告，无源码）。因此决策 1 的「逐条对标原版公开规则说明」此后只能依据
> **本仓 `docs/dev/book-source.md` §3 的规格**与仍在维护的 fork（本次核对用
> `hapelee/legado-with-MD3`）。矩阵的「状态」列仍按原规则由真实书源回归逐行确认，
> M0 / M1 / M2 的范围划分不变。

## 背景

`book-source.md` 初版（v0.1）把规则语法按 P0/P1/P2 排序，但**没有与上游
「原版阅读（Legado）」的实际功能集逐条对标**，导致两处问题：

1. 支持矩阵可能既漏掉原版已有语法，也混入原版没有的语法，兼容性无法度量。
2. 缺少实现分期，无法回答「第一个可导入书源的版本要做到什么程度」。

裁决意见：**先最小实现原版阅读的功能，支持矩阵对标原版。**

## 决策

1. 支持矩阵**逐条对标原版阅读（Legado）公开规则说明**，每条标注：
   语法、示例、原版适用字段、本项目的分期、验证状态。
2. 采用三阶段范围（详见 `docs/dev/book-source.md` §3.1）：

| 阶段 | 范围 | 完成判定 |
|---|---|---|
| **M0**（首个可导入版本） | 默认规则（`class`/`id`/`tag`/`children`/`text` + 位置 + `!` 排除 + 首字符 `-` 反序）、属性提取（`text`/`textNodes`/`ownText`/`href`/`src`/`html`/`all`）、`##` 替换、`\|\|`、`&&`、`@css:`、`@json:`、`@js:`、`{{key}}`/`{{page}}`、搜索/详情/目录/正文四段完整字段、`nextTocUrl`、`nextContentUrl` | 至少 2 个真实书源完成「搜索→详情→目录→正文」离线回放 |
| **M1** | `@put:`/`@get:`、`java.put`/`java.get`、`{{}}` 内嵌规则、`{}` （阅读 2.0）规则、`exploreUrl` 发现页、`canReName`、`isVip`、`java.timeFormat` | 每个语法至少 1 条真实书源验证记录 |
| **M2 / 暂不实现** | `@xpath:`、`:` 正则规则、`webJs`、`sourceRegex`、字体反爬、登录脚本/登录 UI | 命中时必须返回 `ParseFailure(unsupportedRule)` |

3. **命中 M2 语法时禁止静默失败**：必须返回 `ParseFailure(unsupportedRule)`
   并记录 `rulePath`（C-SRC-4）。
4. `@xpath:` 与 `:` 正则规则若要实现，必须先新增 ADR
   （前者需要引入 XPath 依赖，受 C-DEP-1/C-DEP-7 约束）。

## 后果

- **落地顺序由 `PLAN.md` 拥有**（竖切优先：先 1 个书源 + 默认 CSS 规则打通全链路，
  再横向铺开本 ADR 的 M0 矩阵）；本 ADR 只负责**范围分期**，不重复顺序。
- `book-source.md` 的矩阵以「原版语法」为列，状态一律从**待验证**起步；
  每条语法的状态只能由「真实书源回归记录」改为「已确认」。
- 首个发布版本的范围被固定为 M0，评审时可以据此拒绝范围蔓延。
- M2 语法会成为用户可感知的能力缺口，必须在 UI 上给出可读提示
  （`failureUnsupportedRule` 文案已有对应 ARB 键）。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 一次性实现全部原版语法（含 XPath、正则规则） | 需要额外依赖与更大回归面，首个版本无法收敛 |
| 只实现最常见的 CSS + JSON 规则 | 大量书源依赖 `@js:`，兼容性过低；且无法支撑目录/正文分页 |
| 不区分阶段，边做边补 | 无法判定「第一版做完了」，也无法拒绝范围蔓延 |
