# ADR-0085 连续阅读：章节正文跨章接流（滚动与分页共用一份阅读流）

- **状态：** Accepted（2026-10-28，用户裁决：双向连续 + 分页自动接页 + 固定预取 ±1）
- **日期：** 2026-10-28
- **关联：** ADR-0044 §决策 2/4（会话与进度、按比例估算偏移）、ADR-0051 §决策 1（沉浸式与三区点击）、
  ADR-0066 §决策 7（书签跳转的偏移落地）、`docs/dev/constraints.md` C-PERF-1、C-UI-5、C-BAN-1；
  `docs/dev/roadmap.md` §3.7 的「分页模式不跨章连续翻页」登记（本 ADR 结清）

## 背景

阅读器有两种翻页方式（`ReaderPageMode.scroll` / `paged`，默认滚动）。两者都**只渲染当前章**：

- 滚动模式是一段 `SingleChildScrollView`，正文滑到底就是文档结尾。要读下一章只能唤出工具条点
  「下一章」，或者退出重进。
- 分页模式只有在「下一章正文已经预取到」时才能把下一章的页接在后面（M14 的
  `pagedMode_whenTheNextChapterIsPrefetched_turnsAcrossTheBoundary`）；预取没到或失败时，章末给一页
  「本章读完 + 下一章按钮」，仍然要读者点一下。预取的正文在滚动模式下**完全没有被用到**。

上游 Legado 从来不在章界停下（对照 `~/repos/legado-with-MD3`）：

| 上游证据 | 行为 |
|---|---|
| `ReadBook.kt:1381-1389` `loadContent(resetPageOffset)` | 当前章 + `durChapterIndex±1` 一起加载；`loadInitialContent` 先当前章、再相邻章 |
| `ReadBook.kt:1123/1153/1187` | 换章后沿「向后 / 向前」两个方向预取相邻章 |
| `ReadBook.kt:1919-1924` `prefetchNext/PrevChapterEnabled` | 预取由设置 `preDownloadNum` / `preDownloadNumPrev` 门控，**0 = 该方向不预取** |
| `ReadBookController.kt:1061` `continuousScroll = ReadBook.isScroll` | 分页窗口把相邻章的页一起提交，滚动模式也走同一份页表 |
| `ReadBookController.kt:1078-1093` `ensureBoundaryPlaceholderPages` | 邻章未分页时先放**占位页**，手势/滚动因此能自然越过章界，装载完成后以同 id 真实页替换 |

即：上游的模型是「一份跨章的阅读流 + 按需预取相邻章的正文 + 缺正文时用占位页继续」，滚动模式与
分页模式只是同一份页表的两种摆放方式。

## 决策

### 决策 1 一份跨章阅读流，锚点是视口顶

滚动模式把**手上有正文的连续章节**（上一章 / 当前章 / 下一章）竖着堆进同一个
`SingleChildScrollView`；分页模式把同样的章节按 `readerPageStarts` 展开成一条页表。两种模式共用
「窗口」这一概念，定义在新类 `ReaderChapterWindow`：

- **只渲染连续章节**：中间缺一章就不往下拼——否则读者会滑进「没有正文的空白」。
- **窗口有记忆**：已经渲染过的章即使离开页面的预取窗口也留在流程里，避免读者眼前的正文在手指下
  消失；只有滚动停下（`ScrollEndNotification`）时才回收与锚点相距超过 1 章的部分。
- **锚点 = 视口顶**：落在哪一章、章内比例多少，就是会话的章号与字符偏移（沿用 ADR-0044 §决策 4 的
  按比例估算，不引入字符级锚点）。视口顶跨越章界就换章。

### 决策 2 跨章是**换章**，不是跳转

跨章时只把会话移到新章（`selectChapter`，顺带落盘），**不动**滚动/翻页位置：流程实例保留，正文
不重建，视口里的那段字不移动。这与「显式跳转」区分开：

- 显式跳转（目录、书签、进度滑杆、书内搜索、章节按钮、源切换后的对齐）= 换流程实例 + `restore`
  非单调定位，串在 `_restoreNonce` 上（ADR-0066 §决策 7 的同一套语义）。
- 排版变化（字号 / 行距 / 字体）= 也要重建流程，否则视口里的字会整体挪位。

### 决策 3 预取窗口固定为「相邻各一章」，不引入设置项

阅读器对当前章的 `±1` 各预取一次（正文端口 `ChapterContentProvider`，与正常阅读命中同一份 5.2
缓存），预取时携带**与直接阅读完全相同的章节上下文**（目录位置、`nextChapterUrl`、`isVip` / `isPay`
/ `isVolume` / `updateTime`）。这一点是本次一并修的既有缺口：以前预取只传
`bookUrl`/`chapterUrl`/`bookName`/`chapterTitle`，于是「靠预取拿到的正文」与「直接读到的正文」对
`nextChapterUrl` 规则可能给出不同结果（M25/S3b 的绑定），在连续阅读下预取变成了常规路径。

上游的 `preDownloadNum` / `preDownloadNumPrev` 设置**这次不做**，登记在 `roadmap.md` §3.7（触发 =
用户要求「预加载章数可配 / 可关」）。

### 决策 4 拖动期间冻结结构，跳转与排版变化重建流程

- 结构变化（补上前一章 / 回收远处章）会改写「锚点上方的高度」，需要同帧挪动滚动偏移；对着一个
  正在拖动的手势 `jumpTo` 会取消手势。因此**手势进行中冻结窗口**，`ScrollEndNotification` 时再同步。
- 结构变化本身用「锚点上方高度差」补偿（滚动模式）或「页数差」补偿（分页模式），在 build 之前提交，
  所以不会先画一帧错位再跳回来。
- 显式跳转与排版变化直接换流程实例（决策 2），一次定位、没有中间位移。

### 决策 5 缺正文的邻章给占位，不给死路

- 滚动模式：缺的邻章在它将要出现的位置显示 `ReaderChapterPendingStrip`（小号加载指示 + 文案；
  读取失败时换成「重新加载」按钮）。它同时是**接力加载的触发器**：进入一屏范围就向页面要那一章。
- 分页模式：缺的邻章占一页（同样用 `ReaderChapterPendingStrip`）。翻到这一页就发起加载；正文到手后
  **只往后追加页**，所以读者正看的这一页原地变成该章第一页——不跳页、不需要再翻一次。
- 真正的最后一章：滚动模式在正文后显示「已是最后一章」；分页模式在页表末尾多一页同样的文案。
  `readerChapterEnd`（「本章读完」）与它的按钮页随之删除——章界不再是一个要点的动作。

## 修订

- **2026-10-29**：§决策 3 的「预取固定相邻各一章、不做设置项」被 **ADR-0088** 推翻：预取改为两侧各
  15 章、队列化串行；并新增「阅读位置最多跨进一章未加载的章」的上限（页表右边界由锚点章是否就绪
  决定）。§决策 1 的「窗口」模型已在 ADR-0087 换成单一页表。
- **2026-10-28**：§决策 1 的「窗口」实现被替换为**按章节下标派生的槽位**（`ReaderChapterSlots`）：
  每次从会话章算出 `anchor-1 / anchor / anchor+1`，不再保留「已渲染章」也不再按 URL 归并正文。
  原因与取舍见 ADR-0086 §决策 7 与 §修订。

## 后果

- 新增 `presentation/widgets/reader_chapter_flow.dart`（窗口策略 + 占位条）、`reader_scroll_flow.dart`、
  `reader_paged_flow.dart`；`reader_pagination.dart` 增加 `readerTextHeight`（与 `readerPageStarts`
  同一套 `TextPainter` 量法，量高用于锚点换算与结构补偿）。
- `reader_page.dart` 删除 `_scrollBody` / `_restoredScrollText` / `_pagedBody` / `_PagedBody` 与页面自己的
  `ScrollController`；改为按会话章算出相邻三章的正文（新增「排版后的正文」缓存，键为
  `(URL, 段距, 首行缩进)`，C-PERF-1）并交给流程。
- 预取缓存从「当前章 + 下一章」变成「上一章 + 当前章 + 下一章」；内存里仍只保留相邻三章的正文
  （流程自己保留已渲染的章，等滚动停下再回收）。
- 新增 ARB 键 `readerChapterLoading` / `readerChapterRetry`（en + zh），删除 `readerChapterEnd`。
  生成的 `app_localizations*.dart` 随之更新。
- 偏移仍是**按比例估算**（ADR-0044 §决策 4 不变）。跨章后进度写的是新章的比例，因此「读到章末再
  回上一章」落点会有估算误差——与本文无关，仍挂在 §3.7 的那条登记上。
- 视口顶是会话章的唯一判据：最后一章如果短到装不满一屏，它会与上一章同屏且会话仍停在上一章——
  与上游「页的章号取页首段所在章」的语义一致。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 只做向后连续（章末接下一章） | 用户已裁决要双向：向上滑回上一章尾部是同一个阅读动作，只做一半等于换个地方撞墙 |
| 只修加载、不接流（章末自动拉下一章并换会话） | 视觉上仍是一次重排/闪动，上游不是这个行为；用户裁决要求与上游一致 |
| 新增「预加载章数」设置项 | 上游有，但这是新的设置模型 + 仓储 + ARB + UI 面；本次先把行为对齐，设置面登记待触发 |
| 每个段落一个 `ListView` 项（懒加载正文） | 段落项高度不固定，锚点与补偿都要按段落做，反而更复杂；正文规模（单章几十 KB）不值得 |
| 每跨一章就重建流程实例 | 重建要重新定位，正是一次闪动；且会丢掉上一章尾部，等于只做向后连续 |
| 用字符级锚点替代比例估算 | 需要把锚点写进章节模型并版本化，属数据格式决策（ADR-0044 §决策 4 仍登记为未做） |
