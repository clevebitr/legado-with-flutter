# ADR-0045 书源列表的展示与排序：投影列为准、固定 tie-breaker、拖拽归一化

- **状态：** Accepted（2026-10-21，M6 / roadmap §5.5 规格前置，用户裁决四项）
- **日期：** 2026-10-21
- **关联：** C-ARCH-2、C-NET-9、C-UI-5、C-UI-7、ADR-0040、ADR-0043、`docs/dev/roadmap.md` §5.5、
  `docs/dev/architecture.md` §6

## 背景

§5.5 只写了一句话：`lastUpdateTime` / `respondTime` / `weight` / `customOrder` 的展示与排序，加上
校验 / 调试入口。入口随 M10 已经落地，剩下的是**列表本身**，而它牵出四件必须先定死的事：

- M10 把校验结果写进的是**列**（`groupName` / `comment` / `respondTime`），而 `StoredBookSource` 现在只暴露
  `payload` 解析出来的 `BookSource`。不决定「以谁为准」，列表就会显示校验之前的旧分组；
- 排序键不止一个，需要一条**并列时的固定次序**，否则同一份数据在不同次查询里会换位置；
- `customOrder` 要能拖拽编辑，而「拖完怎么编号」是数据决定，不是 UI 细节；
- 排序键与分组筛选是**用户选择**，要不要记（C-NET-9）。

## 决策

### 决策 1 列表以**投影列**为准，`StoredBookSource` 暴露它们

- `StoredBookSource` 增加五个来自列的只读投影：`groupName`、`respondTime`、`weight`、`lastUpdateTime`、
  `comment`。它们**不是** `payload` 的拷贝：M10 的校验只改列，`payload` 逐字节保留（ADR-0040 §决策 4）。
- 展示与排序一律读列。`groupName` 为空时回落到 `source.group`（老行的初值就是负载值，回落只是保险）。
- 这条是 ADR-0040「列 = 用户态 + 投影，负载 = 导入原文」的直接推论，此处只把它写到接口上。

### 决策 2 四个排序键，外加一条**固定 tie-breaker**

| 排序键 | 主次序 | 语义 |
|---|---|---|
| `defaultOrder`（默认） | `customOrder` 升序 | 手动序；未拖动过就是导入顺序 |
| `weight` | `weight` 降序 | 源自己声明的权重，越大越前 |
| `respondTime` | `respondTime` 升序，NULL 最后 | 校验耗时；**没校验过的不当 0 ms**，排在有值的后面 |
| `name` | `name` 升序（code unit，不接 collation） | 按源名；中文按 UTF-16 码元，不做 pinyin |

**所有键后面固定追加**：`isEnabled` 降序 → `customOrder` 升序 → `id` 升序。

- 「启用的排前面」对所有键都成立：禁用源不是「更差的源」，而是「不参与搜索的源」，任何排序下都不该混在
  启用源中间抢位置。
- 后两级让同一份数据**任何一次查询都得到同一顺序**（`customOrder` 可能相等，`id` 由 `AUTOINCREMENT`
  保证单调）。
- `respondTime` 的空值语义是这条决策的重点：`NULL` 表示「从未校验」，`0` 表示「校验了，几乎瞬间返回」，
  把两者混为一谈会让未校验的源永远置顶。

### 决策 3 拖拽只在默认序下可用，落盘时**整体归一化**

- 拖拽写 `customOrder` 的规则：把当前列表按新顺序编号为 `0..n-1`，**一次事务**写回全部行。
  不做「相邻两行交换」——交换在中间值相同时会得到不确定结果，而整体归一化是幂等的。
- 只有 `defaultOrder` 下允许拖拽：其它排序键下「顺序」不是用户的意图（例如按权重排时拖动，松手后
  列表会跳回去），因此那些键下 `ReorderableListView` 退化为普通列表，排序菜单里说明这一点。
- 拖拽写的是**全部行**（含禁用源），因为 `customOrder` 是全局序，不是「启用源的相对序」。

### 决策 4 排序键与分组筛选持久化在 `book_source/data/`

- `BookSourceListView`（排序键 + 分组筛选，两者都可空）存 `shared_preferences`，键私有于
  `lib/features/book_source/data/`（C-NET-9 的同一条规则：键只有一处拼写）。
- 读回时**校验排序键**：未知的名字回落到 `defaultOrder`（枚举是存储层自己的词汇）。筛选的**分组**不在存储层校验：
  分组是否还存在取决于当前行集合，而存储层看不到行 —— 由列表在渲染时回落到「全部」（显示期回落，不从 `build`
  里写回修正），与上游 `SearchScope.getBookSourceParts` 的回落同一条思路。
- 不进设置页：这是**列表自己的**视图状态，不是全应用偏好（与 5.6 的分工）。

### 决策 5 展示字段与格式

- 行内展示：**分组**、**最近更新**、**响应耗时**、**校验注释**（用户裁决）。
- 「最近更新」用 `lastUpdateTime`（毫秒时间戳）经 `MaterialLocalizations.formatShortDate` 渲染：
  不引入 `intl` 依赖（C-DEP-1），也不手写 `yyyy-MM-dd`（那样既不受 locale 影响也不受日历系统影响）。
- 「响应耗时」以 `ms` 显示，**空值不显示**（不是 `0 ms`）。
- 「校验注释」只显示第一行（`maxLines: 1` + 省略号），完整文本通过行内的注释按钮打开对话框查看：
  一条 `// Error: …` 可能有几百字，塞进行内会把列表撑歪。
- 所有文案走 ARB（C-UI-5）；`groupName` 里的 `搜索失效` 一类 token 是**数据**（ADR-0043 §决策 4），
  照原样显示，不翻译。

## 后果

- `BookSourceRepository.getAll` 多一个可选排序参数；现有调用点（默认序）不需要改。
- 新增 `reorder(List<int> ids)`：一次事务写 `customOrder`；报告影响行数（0 表示全部行都消失了）。
- 列表页在默认序下换成 `ReorderableListView`，其它序下是普通 `ListView`；分组筛选是列表上方的 chips。
- 「排序 + 筛选」是**列表页**的状态，校验页 / 调试图的选源逻辑不受影响（M11 会把两者合并成一套选源逻辑，
  届时以本 ADR 的排序口径为准）。
- 覆盖率：新增的 DAO / 仓储 / 偏好实现都在门禁范围内（core 100%、data ≥80%），DA0 的排序分支逐条测。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 列表继续显示 `payload` 里的分组 | M10 的校验结果永远不显示；「重新校验前先清掉」也就看不出效果 |
| 排序在主存里做（`StoredBookSource` 列表排序） | 排序键有一半是列（`respondTime` / `comment` 不在负载里），主存排序会漏键；而且 `getAll` 已有 SQL 排序，两个地方排会漂移 |
| `customOrder` 用相邻交换 | 中间值相等时结果不确定；归一化幂等且一次写完 |
| 拖拽在所有排序键下都可用 | 用户拖完松手列表会按其它键跳回，等于「拖了没反应」 |
| 未校验源的 `respondTime` 当 0 参与升序 | 未校验的源会挤到最前面，把「响应最快」这件事变成「响应最不确定」 |
| 注释全文塞进行内 | 一条注释几百字，行高会被撑开，列表滚动变难；对话框是更适合长文本的容器 |
| 排序/筛选只放内存 | 每次进列表都要重选；而这是用户明确表达过的视图偏好（C-NET-9 的轻量开关） |
