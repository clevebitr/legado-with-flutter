# ADR-0050 书源管理的写路径：用户分组与校验分组、批量操作、编辑后的身份、单条导出

- **状态：** Accepted（2026-10-22，M13 规格前置；范围由 `DECISIONS.md` #11 的用户裁决给定）
- **日期：** 2026-10-22
- **关联：** C-BAN-2、C-DATA-*、C-ERR-8、ADR-0019、ADR-0021、ADR-0040、ADR-0043、ADR-0045、
  `docs/dev/roadmap.md` §3.9（S2–S5）、`docs/dev/book-source.md` §2

## 背景

M13 要让书源管理能**写**：批量改状态与分组、编辑单条书源、导出单条。现有实现只写了三条路径
（导入、启用/禁用、校验回写），而它们对「分组」这个词的用法互相冲突：

- `bookSourceGroup` 在 **payload** 里，是书源作者写给用户的**用户分组**（"玄幻"、"API"…）；
- `groupName` **列**是 M10 校验写回的**校验分组**（"搜索失效"、"目录失效"…），ADR-0045 §决策 1 要求
  列表以列为准；
- 现在的列表行取的是 `source.groupName ?? source.source.group` —— **校验一跑，用户分组就被失效分组顶掉**。
  用户点名的「支持显示全正常的书源分组」正是这条错位造成的：全正常的源没有 `groupName`，于是分组列
  显示的是 payload 里的分组；跑过一次校验的源显示的是「搜索失效」。两者混在同一个筛选维度里。

编辑单条又牵动 ADR-0040 的身份：唯一索引是 `(bookSourceUrl, 行为指纹)`，而指纹由**行为字段**算出——
编辑改了 URL 或任一规则就会改指纹。

## 决策

### 决策 1 用户分组与校验分组是两个维度，永不混写

- **用户分组**（`bookSourceGroup`）读 payload，写 payload；它是用户态，只能由用户操作改。
- **校验结论**（`groupName` / `comment` / `respondTime` 列）只由校验写，只用于「失效/正常」判断与注释展示。
- 列表行的副标题显示**两者**：用户分组 + 校验分组（有的话），带各自的标签，不做 `??` 合并。
- 筛选有两个轴：
  - **分组**：来自 payload 的自带分组（覆盖**全部**自有分组，包括没有任何校验标记的源）+
    `未分组`；
  - **校验状态**：`全正常` / `有失效`。判据是 `comment` 或 `groupName` 是否含本仓写入的失效分组标记
    （`source_check_group.dart` 的常量，唯一出处）。「全正常」= 从没校验过**或**校验通过且无注释。
- 因此用户点名的「显示全正常的书源分组」落地为：分组轴列出全部分组（不再被校验分组污染），
  校验轴可以一键只看全正常。

### 决策 2 批量操作是一个事务，且只碰用户态

- 新增 DAO 方法：`setEnabledFor(ids, isEnabled)`、`deleteByIds(ids)`、`writeGroupFor(ids, group)`。
  每一个都在**单个事务**里做完全部行，避免「删了一半」的状态。
- 批量只改**用户态**（`enabled` / `customOrder` / payload 的 `bookSourceGroup`）；不碰校验列。
- 删除后当前选中源的回落由现有适配器逻辑负责（5.1 已实现：选中的行被删 → 回落到默认源），
  批量删除复用同一条回落路径。
- 批量**不**提供「批量校验」的新入口：它已存在（校验页全选），加两个入口只会让「到底跑了哪些源」
  有两个答案。

### 决策 3 编辑更新**同一行**；身份冲突是显式失败，不静默合并

- 编辑页按 `id` 保存：重写 payload、重算指纹、同步列投影（`url` / `name` / `sourceType` / `groupName`?
  **不**——`groupName` 是校验列，编辑不许写它）。用户态（`enabled` / `customOrder`）保持原值。
- 若新指纹与**另一行**的 `(url, 指纹)` 相同 → **拒绝保存**，提示「这次修改和已有的另一份完全相同」，
  并给出那一行的名字。理由：ADR-0040 让同 URL 的**不同**规则共存是有意的，而「完全相同」没有信息量；
  自动合并会删掉用户可能正在用的行，自动共存会违反唯一索引。
- `url` 改了的行**不会**自动迁走书架 / 阅读进度：它们的身份是 `(sourceUrl, bookUrl)`（ADR-0041 §决策 4
  的落地口径），换 URL 等于换源。编辑页在 URL 被改动时显示一行提示（不阻止保存）。
- 保存前一律用 `BookSource.fromLegadoJson` 校验（checked 模式，ADR-0022）；失败按字段报告，
  不写库。

### 决策 4 单条导出 = payload 原文，不做 `toJson`

- 导出的字节就是 `payload` 列（ADR-0040 §决策 4 的保真口径），**不**从模型 `toJson` 重建——那会丢掉
  `extra` 未建模字段与原始键序（ADR-0021 §后果已登记）。
- 形态：复制到剪贴板 + 保存为文件（`file_selector` 已在依赖里，5.8 的文件选择半程已落地）。
  批量导出与「分享」不在本轮（5.8 的范围）。

## 影响

- `lib/core/storage/book_source_dao.dart`：三个批量方法 + `updatePayloadById`（编辑保存）。
- `domain/repositories/book_source_repository.dart` 与 `data/` 适配器：对应端口方法。
- `presentation/notifiers/book_source_list_notifier.dart`：分组轴 / 校验轴两个筛选状态、多选集合、
  批量动作；分组列表从 payload 派生（`StoredBookSource.source.group` 已可用）。
- 页面：`book_source_list_page.dart`（多选模式、搜索框、两个筛选轴、行菜单新增校验/编辑/导出）、
  新 `book_source_edit_page.dart` + 路由。
- 校验分组常量仍是 `source_check_group.dart` 的唯一出处；本 ADR 不复制清单。

## 后果

- 好的方面：「全正常的书源分组」有了明确语义；校验不再污染用户分组；批量与编辑都只写一个事务；
  编辑撞身份时用户看到原因而不是数据被悄悄改掉。
- 代价：`groupName` 列从此**只**表示校验结论，5.10 的写入方与 5.5 的展示方都要按这条读；
  列表行的副标题比现在多一行标签。
- 未闭环：批量导出 / 分享（5.8）；编辑页不迁书架与进度（有意，见决策 3）。
