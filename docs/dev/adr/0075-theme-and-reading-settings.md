# ADR-0075 M22-d：主题配置与阅读设置扩展（U9 / U10）

- **状态：** Accepted（2026-10-25，用户四项裁决：主题 = 配色 + 背景图；阅读设置 = 亮度 + 进度条 + 背景；
  亮度用页内遮罩；背景图复制进应用目录）
- **日期：** 2026-10-25
- **关联：** `docs/dev/ui-gap.md` §3 U9 / U10、§4 M21；ADR-0004（m3e 令牌与动态取色）、ADR-0044
  （阅读器四轴与 `ReaderSettings`）、C-UI-1/3/8、C-NET-9、C-PLT-3

## 背景

U12 备份已经落地（ADR-0073 / ADR-0074）。本轮做的是「可配置」追上上游的那一半：

| 项 | 上游落点 | 本仓现状 |
|---|---|---|
| 配色管理 | `ui/theme/*`、`ThemeConfigStore` | 只有 `themeMode` 三档 + Android 动态取色；没有种子色选择 |
| 背景图（应用 / 阅读） | `ui/config/themeConfig/*`、`ReadBookConfig` | 没有；阅读器只有四个纯色背景 |
| 阅读亮度 | `ReadBookConfig.readBrightness`（窗口属性） | 没有 |
| 进度条行为 | `readConfig` 的进度条位置/自动隐藏 | 阅读器只有一个固定进度指示 |

## 决策 1 主题 = 种子色 + 背景图，导航栏位置与图标包本轮不做

- `AppSettings` 新增 `seedColor`（`int`，ARGB）：未选时为 `defaultSeedColor`，选了就替代动态取色的
  fallback 种子色。**动态取色仍然优先**（ADR-0004）：系统给了 `ColorScheme` 就用系统的，用户选的
  种子色只决定「没有动态取色时」的主题（Windows / iOS / 关掉动态取色的 Android）。
- 页面：设置页新增「主题」一节——6 个预设色 + 一个「跟随动态取色」开关复位；点选即写入
  `shared_preferences` 并重建主题（`settingsProvider` 已 keepAlive，`invalidate` 即可）。
- **背景图**：`AppSettings` 新增 `backgroundImageName`（相对文件名，不是绝对路径）。选图走既有的
  `CoverFilePicker` 形态的新端口，选中的文件**复制**进应用支持目录的 `backgrounds/`，只把文件名入库。
  理由：用户原图被移动/删除、或 Android 的 URI 授权过期后，绝对路径会变成一张打不开的图；
  复制一份是唯一「选了就一直有效」的语义（用户裁决同此）。
- **不做**：导航栏位置（底/顶）、tab 图标包、启动图标——它们改的是外壳布局与三端资源，需要自己的
  ADR 与三端截图验收，登记在 `roadmap.md` §3.7。

## 决策 2 阅读设置 = 亮度 + 进度条行为 + 背景图

- `ReaderSettings` 新增三个字段：
  - `brightness`（`0.4..1.0`，默认 1.0）：**页内遮罩**，不是系统亮度。
  - `progressBarMode`（`always` / `autoHide` / `hidden`，默认 `autoHide`）：`autoHide` 在滚动/翻页后
    3 秒淡出，点屏幕中区或打开菜单时回来。
  - `useThemeBackground`（`bool`，默认 `true`）：开启时阅读器用主题背景图（若有）叠加在当前纯色背景
    之上，关闭时保持现有纯色四选一。
- **亮度用遮罩**（用户裁决）：一层黑色半透明 `IgnorePointer` 盖在正文上，`opacity = 1 - brightness`。
  不碰系统设置 → 零平台通道、三端一致、退出阅读器自动恢复，也不会改动用户的系统亮度。
  代价：屏幕最亮时「调亮」无效（遮罩只能变暗），页面文案写「降低亮度」而不是「调节亮度」。
- 三个字段与既有四轴（字号/行距/背景色/翻页方式）同存 `shared_preferences`（C-NET-9），
  都与全局 `fontScale` **叠乘/叠加**而不是替换（ADR-0044 §决策 1 的同一口径）。

## 决策 3 背景图只有一个来源，阅读器只管「用不用」

- 主题的背景图（决策 1）是唯一来源；阅读器不提供第二张图。`useThemeBackground` 关闭时阅读器
  回到纯色，但不清空主题背景图（两者是不同层级的选择）。
- 背景图与遮罩可以叠加：图在最底、纯色背景在其上（可选的不透明度由纯色背景本身决定）、
  遮罩在最上层。三者顺序写死在一处，避免「同一张图两个页面亮度不同」。

## 后果

- 主题从「三档模式」变成「模式 + 种子色 + 背景图」，设置页多一节；`app_theme.dart` 的种子色
  从常量变成入参（`defaultSeedColor` 仍是唯一默认值，C-UI-1 的例外不变）。
- 阅读器多三个字段与一个遮罩层；`ReaderSettings` 的仓储要能容错读旧值（未知枚举索引回落默认，
  与现有实现一致）。
- 背景图是用户数据：备份的 `preferences.json` 会带上 `backgroundImageName`，但**图片文件本身不在 zip 里**
  ——恢复后若本机没有同名图片，阅读器回落到纯色并在设置页提示「背景图缺失」（登记项）。

## 登记（`docs/dev/roadmap.md` §3.7）

- 导航栏位置 / tab 图标包 / 启动图标：需独立 ADR 与三端验收。
- 系统亮度联动（`WRITE_SETTINGS` / Windows 原生）：遮罩之外的第二条路，触发 = 用户反馈「遮罩压不到
  环境光」。
- 翻页键位（音量键、方向键）：要平台通道拦截按键；触发 = 用户要求在阅读器里用音量键翻页。
- 背景图文件不进备份（只进文件名），以及「多张背景图轮换」：触发 = 用户要求换机保留背景图。
